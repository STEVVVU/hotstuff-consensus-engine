# Frozen network and fault benchmark

Use `python tools/benchmark.py smoke` after building scratch/hotstuff.exe and scratch/campaign.exe with the repository's Go flags. `--hotstuff PATH` selects a freshly built smoke binary without overwriting an existing binary. Smoke runs the real TLS/ECDSA loopback CLI with four replica goroutines, checks identical nonzero executed command counts/order hashes, and verifies exact raw dispatch/terminal accounting. Timings are instrumentation evidence only. `python -m unittest discover -s tools -p test_benchmark.py -v` covers axes and a synthetic private-key exclusion control. Client measurements have a deterministic pending-at-shutdown/queue-latency Go regression.

`python tools/benchmark.py benchmark` requires isolated Linux. Version1 uses seed421, replicas4/7, payload32/1024/8192bytes, clients1/4, max concurrency4/32 and total offered100commands/s for10s in six one-axis cells, repeated five times with reverse order. Baseline is four replicas, one client, concurrency4 and1024-byte payload. The opt-in client-commands metric uses a deterministic payload reader seeded421+clientID and records each actual payload SHA256, desired arrival, pre-RPC dispatch and terminal outcome. It preserves default scheduling, default input reader, quorum and existing aggregate logger when absent. A direct synchronous observer avoids losing shutdown-pending events through a canceled event loop; per-client raw logging caps262144records then emits overflow and invalidates the run. Pending storage stays bounded by the actual concurrency window. Errors are capped512bytes. No signatures or private keys enter raw command samples.

Planned offers, dispatched, extra/not-dispatched, finished, failed, timed-out, canceled, canceled-pending and unresolved counts are distinct. Canceled may still commit and never implies lost consensus work. Native CLI shutdown cancels in-flight pipeline commands; all remain in whole-run receipts. For offered30/100/300/1000rate sweeps, the separately labeled steady window excludes the first2s warmup and last2s shutdown boundary, requires every scheduled interior command dispatched/completed, dispatch-p99<100ms and finality-p99<5s, and chooses the highest qualifying rate for120s stability. Whole-run cancellations/errors are never discarded from reports. This is bounded-client load; scheduled latency exposes generator backlog, while planned-but-undispatched counts expose omission. Client finality means the inherited f+1 execution replies, alongside complete replica count/hash agreement.

Separate `profile` invokes native CPU/memory flags for30s and excludes those timings from comparison. Linux resource samples track the owned native process and generator every100ms. Source/dirty/environment, complete raw samples and safe metrics survive under ignored scratch/benchmark-* with confirmed owned cleanup.

Never upload raw upstream measurements.json. It contains orchestration options including ephemeral PrivateKey/CertificateKey fields. The driver allowlists command metric fields and throughput fields, writes metrics-safe.json and sanitizes only its own fresh measurement file after process exit. Failed raw files remain ignored and outside workflow artifact paths. The synthetic negative control proves option records and injected unknown key fields cannot survive the export. Twins keys remain in memory; this distinction corrects older broad wording about all network evidence.
